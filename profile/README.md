<p>稳定性是个被用滥的词，不同人说它时指的不是一件事。本文先把稳定性拆成四个可观察的指标，再分类掉线来源，然后讲长期运行会累积的资源问题、监控怎么做、续费环节的风险，最后给一套长期使用的操作纪律。</p>
<h2>一、"稳定"要拆成四个指标</h2>
<p>第一是在线率，一天里能连通的时间占比。第二是抖动，延迟在多大范围内波动。第三是恢复时间，断了以后多久能自己恢复。第四是地址不变，租期内是不是始终同一个。</p>
<p>四个指标经常不同步。有的线路在线率很高，但抖动大，后台操作一顿一顿；有的延迟平稳，却每月断一次且要人工重启。先确定自己最在意哪一项，再谈好坏。</p>
<h2>二、掉线的常见来源分类</h2>
<p>一类在住宅侧：光猫重启、运营商夜间维护、小区线路改造，不可控，只能靠备用出口顶。另一类在机房侧：服务器过载、被攻击、磁盘写满导致服务退出。</p>
<p>第三类在自己这侧：本地网络切换、客户端版本升级、防火墙规则变化。实际排查里，第三类占比不低，但最容易被忽略，因为大家本能地先怀疑服务商。</p>
<h3>怎么判断是哪一侧掉的</h3>
<p>看同一个出口是否只有你连不上。用另一台设备、另一条网络各试一次，两边都不通偏向服务端，只有一边不通偏向本地。再对照服务商的公告时间，基本能定性。</p>
<h2>三、长期运行会累积的问题</h2>
<p>跑得越久，连接数、内存、日志体积都在往上走。长连接若没设回收，几千个空闲连接会吃光文件描述符，表现是新连接一律失败。</p>
<h3>磁盘是怎么被一点点吃掉的</h3>
<p>日志和抓包文件也容易忘。一台小磁盘的机器，日志写满根分区后服务直接崩，重启也只撑几小时。设个轮转策略，比事后清理省事得多。</p>
<h2>四、监控：先知道它什么时候不稳</h2>
<p>低成本监控是定时探测：每五分钟发一次带认证的请求，记录耗时与结果，连续三次失败就告警。数据攒两周，抖动和掉线的时间规律就浮出来了。</p>
<p>告警要区分"抖一下"和"真断了"：抖动看连续失败次数，真断看恢复时间。没有区分的告警会让人麻木，最后连真故障也当噪音。</p>

<h2>五、套餐与续费上的风险</h2>
<p>按月付灵活，但很多服务商不支持中途退，且到期当天就停。按年付便宜，缺点是提前锁定，服务商换线路或调整资源时你没有议价空间。</p>
<p>续费前确认三件事：地址是否保留、带宽是否缩水、价格是否按新价执行。有些首月价和续费价差一倍，没看清就在第二个月被动接受。</p>
<h3>到期前一周该做什么</h3>
<p>把新环境的地址提前开出来，导一份配置，跑两天对比延迟和丢包，再决定续还是换。临时抱佛脚往往是随意选一家，把问题带到下个月。</p>
<h2>六、长期使用的操作纪律</h2>
<p>固定设备、固定时段、固定出口，三个固定能挡住大部分不确定性。变更时一次只动一项，动完观察两天，别在业务高峰调整。</p>
<p>再留一条备用路径：不同机房的地址，或一台能临时顶上的VPS。备用不必多好，业务不断就行，切换十分钟内完成即可。</p>

<h2>常见问答</h2>
<h3>在线率百分之九十九算稳定吗？</h3>
<p>答：要看到九十九是怎么分布的。三次各断二十分钟，和一次断七小时，数字接近但影响差很多，还要看断的时间是否落在业务时段。</p>
<h3>长期不重启会不会越来越慢？</h3>
<p>答：可能。连接残留、内存碎片、日志堆积都会让性能下滑。建议定期重启并清理临时文件，重启前后各做一次基线测量。</p>
<h3>静态住宅IP也会换地址吗？</h3>
<p>答：正规服务在租期内不主动更换，但迁移、线路调整、故障重建可能导致变动。日常记录出口地址就能及早发现。</p>
<h3>需要自己搭监控系统吗？</h3>
<p>答：不必上复杂系统。一个定时脚本加一份表格，记录时间、耗时、结果，就够看出趋势。规模上来再换带告警的工具。</p>
